# 教材主导的 AI 学习工作流

规划课程、分配阅读、准备补充材料或根据作答调整进度时读取本文件。主教材承担系统讲授；AI 负责导读、补足教材与当前基础之间的缺口、核验和组织练习。不要默认重写已分配的全部教材内容。

## 先诊断，再决定读什么、补什么

先提取已有目标、教材、时间和表现。用少量逐题任务检查关键先修、概念/符号理解、推理或实践能力；必要时让用户试读一个很短的段落，观察真实阅读负荷。自报、实际作答和未测分开记录，不能凭“新手”“读过”推断掌握。

把诊断明确落实到计划：这条证据说明哪些内容可快过，哪一项需要补前置，本次读多大范围，验收什么。未知项用首课短任务继续诊断，不无限延长入门测试。没有基础的主题先给必要入门支撑，再检查理解。

| 观察到的表现 | 相应安排 |
| --- | --- |
| 基础任务独立正确，能解释依据 | 压缩重复阅读；保留一次变式确认，把时间用于新的依赖关系和迁移 |
| 定义/量词/术语混淆 | 缩小阅读段，先补必要逻辑或词义；随后回到同一教材位置重读 |
| 会复述、不能解释或选择方法 | 增加推导、条件辨析与方法选择任务，不只追加页数 |
| 过程正确但边界/执行出错 | 保持主题进度，安排定向练习与反馈；不重新讲完整基础课 |
| 只有看书、看范例或 AI 提示后的成功 | 保留辅助程度，安排新的独立任务；不能直接跳过验收 |
| 内容和迁移均独立通过 | 可以进入下一部分，同时安排课内延迟复测 |

这些是调整依据，不是给所有学科套相同分数线。阶段通过标准须覆盖预先约定的核心目标，允许资料和提示程度都要明确。

## 每次给一张可执行的阅读任务卡

一张卡只覆盖当前适合学习的一块内容，并保存至当前课次或必要的课程 work/ 文件：

1. **位置与目标**：当前阶段、主题、地图上的前置/后续；读完能解释或做什么。
2. **准确范围**：教材名、作者、版次、章节/小节、起止位置、必要题号；只在已核对时给页码。纸书页码与 PDF 阅读器页序分开注明；EPUB/网页版用章节、定义或定理编号定位。只知道目录时不假装已读正文，也不编造页数或习题。正文不可得时说明缺口，先采用已验证的可用材料。
3. **读法与取舍**：哪些定义精读、哪段证明先抓结构、哪些细节可暂略；有必要时标明读到哪里停下。把基础快速补齐和深读的范围分开。
4. **少量读前问题**：通常 2–4 个，指向动机、关键条件、论证或后续用途；不给完整结论与验收答案。
5. **阅读产出**：例如用自己的话给出定义并保留量词，标出证明中两条依赖，提交一个例子/反例或疑问。不要要求重抄教材、做大量美化笔记。
6. **时间与检查点**：阅读、补充、练习、复盘全部入账；可以分几轮完成。到检查点等待用户真实反馈，不自行假定已读完。

两小时预算示例：10 分钟旧知识提取/针对性诊断 + 5 分钟导读 + 35 分钟教材阅读 + 15 分钟针对性补充 + 10 分钟休息 + 30 分钟练习与验收 + 15 分钟复盘 = 120 分钟。依据证明密度、语言难度和实际阅读速度调整，不能只按页数衡量负荷。额外必做阅读或练习必须计入总投入。

用户说“读完了”只记录阅读自报，接着用短任务检查理解。用户卡在阅读中时及时补讲，无需等整段读完。读后检查可以先于补讲；正式阶段验收应在有学习和练习机会后进行。

## 一个主题怎样使用 AI

以下是按需调用的工作流，不是每课必须生成的全部产物。主动选当前最有价值的一项，说明它解决哪个缺口。产物落在课程档案/课程 work/ 中，不放入 Skill 发布仓库。

| 主题与输入 | AI 生成的内容 | 学习者的动作 | 如何检查 |
| --- | --- | --- | --- |
| 新领域 + 目标 + 诊断证据 | 总体地图、先修关系、主教材选择和总学时/课次 | 确认实际用途，完成必要诊断 | 路线与实测起点一致，未知项清楚 |
| 一个小节 + 当前能力 | 上述阅读任务卡 | 按范围读，带回短产出/疑问 | 一次一个理解问题，按回答决定补充 |
| 一个定义/机制不清 | 精确重述、符号/量词拆解、一个相关例子与必要反例 | 重述条件，判断新对象是否满足 | 检查条件、变量依赖和区分能力 |
| 一段证明/推导/程序卡住 | 所用前提、关键缺步、为什么选择这条路线；必要时给不同例题示范 | 补关键步骤或独立重做 | 检查是否能说明依据，避免照抄算通过 |
| 一个主题在多本教材中的对应章节 | 经核对的概念对照与阅读取舍表 | 只读确实能补缺口的部分 | 用统一记号重述并说明差别为何产生 |
| 关系复杂或参数变化难想象 | 概念依赖图、思维导图，或一张图/一个小型交互 HTML | 先预测，再操作/观察，解释差异 | 用新问题核验；看过图不能算掌握 |
| 一课/阶段结束 | 未见变式、条件辨析、组合任务或实际操作 | 在约定资料条件下独立完成 | 记录证据、提示和错误，决定补强/推进 |
| 隔日或下一课 | 少量混合复测和必要计划修订 | 从记忆提取并自己选择方法 | 延迟表现与当堂表现分开记录 |

## 补充讲解的深度与语言

以“当前问题 → 所需定义/机制 → 关键推理 → 相关例子/反例 → 与主线联系”组织。简洁指减少重复和无关话题，不删去假设、量词、推理理由或边界。用户要求深挖时分小段展开，并在关键处留出作答空间。

先快速补必要基础，再深入到为什么这样定义、解决了什么问题、定理如何从前提构建、与哪些后续内容相连。动机与严格证明分开；教学重构不能冒充作者思考史。不要默认用生活类比替代专业解释，例子必须直接服务于当前概念或错误，能用领域内例子说明就优先使用。

对用户正在做的目标练习，先给最小必要提示或不同的示范题；完整解答只有在教学确需或用户要求时提供，并如实记录辅助。必要补讲不能变成让新手盲猜。

## 多教材如何联系

保留一本主线，辅助教材只解决明确问题。比较前核对各自正文、版次和对应位置；没有正文时只给待核对的比较方向，不声称某书遗漏、错误或证明更好。

对照表按需包括：对应位置、定义与记号、定义域/假设、结论强弱、证明路线与先修、例题/习题用途、建议先后顺序。区分记号不同、等价表述、假设不同和真正矛盾；例如换了定义域后结论变化，不是教材互相冲突。给出一句可执行结论：“主书读到这里，副书只补这一段，因为当前缺口是……”，额外阅读计入预算。

## 地图、图示和 HTML

先给小规模全局图定位当前主题，再按进度展开局部依赖。标明节点是问题、定义、等价判别、定理、方法还是应用；箭头注明“需要/推出/等价/推广/对比”，写上会改变结论的条件。章节阅读顺序不等于证明依赖，不能画出循环论证或把不可逆命题画成等价。

学科/阶段图放在 ROADMAP.md；有实际作答支持时才标记已掌握。可以让用户补回关键关系以评估理解，不只观看成图。数学示例见 [连续性的阅读与补充示例](continuity-example.md)。

简单关系优先文本或 Mermaid，静态定量图用合适绘图工具。只有调整参数或逐步操作能帮助理解时才制作 HTML；优先自包含、可在本地打开，注明定义域、坐标、参数、假设和图例。先让用户预测，再显示结果。有限采样或动画不证明全称命题。

交付 HTML 时实际检查关键控件和边界输入；没有可用预览工具时说明未验证交互并给静态替代。补充材料的生成、工具操作和版本排错由 AI 承担，不占用学习者的思考任务。

## 保存并继续

保存本轮派读范围、用户自报读到的位置、已完成的补充、未答问题、实际作答证据、地图/图示路径和下一步。阅读完成、内容已讲、练习完成、独立掌握分开记录。根据证据更新后续范围、节奏与复测，不自行重置整门课或追加未计入预算的任务。
